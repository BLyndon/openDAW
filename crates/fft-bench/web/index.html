How the kernel came about

  1. Round 1: the prototype simd

    7.4× faster than today's rfft (lowest of N = 1024–16384, Node, M1), all accuracy gates passed.

    Five steps on the textbook FFT: real-input trick, radix-4 Stockham, twiddle tables per stage, f32x4 butterflies, unchecked vector access.

    Docs: crates/fft-bench/docs/simd-kernel.md

  2. Round 2: outlook items O1–O10

    Only O1 and O4 gain reliably: O1 +5–13 % forward, O4 +3–7 % forward and inverse (N = 1024–4096, two Chrome runs).

    Seven items built as cumulative stages on simd, timed on the stages page.

    Docs: crates/fft-bench/docs/simd-outlook.md

  3. Selection: simd-o1o4

    The own kernel we take forward: 10–19 % faster than simd forward (N = 1024–8192, Node), same bits, 1.7 kB more.

    Kept: faster at N = 1024–4096 in both runs, same bits. Left out: O2 (changes bits), O3 (slower at small N), O5 (large N only), O10 (noise).

  4. Comparison: realfft

    realfft takes 1.5–1.9× as long as simd-o1o4 at every size (Node), adds 172.6 kB and does not link no_std.

    The decision page measures all options live in this browser; it recommends no option.
